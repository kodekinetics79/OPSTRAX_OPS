# External Inputs Required for Staging / Production Deployment

This document lists exactly what must be provided by the deployment owner (Zahid / customer) before OpsTrax can go live in staging or production. Nothing listed here can be generated by the engineering team — these are external credentials, decisions, and provisioning actions.

---

## 1. Hosting

| Input | Description | Required for |
|---|---|---|
| Deployment platform | AWS, GCP, Azure, Railway, Render, Fly.io, or other | Staging + Prod |
| Staging URL | Public HTTPS URL for the staging environment | Staging |
| Production URL | Public HTTPS URL for the production environment | Prod |
| Platform admin URL | URL for the `/platform/` control plane (may be same host) | Staging + Prod |
| TLS certificate | Valid TLS cert for staging and production domains | Both |
| Deployment access | CI/CD credentials or manual SSH/deploy access | Both |

**ENV vars produced:**
- `APP_BASE_URL` / `OPSTRAX_BASE_URL`
- `PLATFORM_BASE_URL` / `OPSTRAX_PLATFORM_BASE_URL`

---

## 2. Database (PostgreSQL)

| Input | Description | Required for |
|---|---|---|
| PostgreSQL connection URL | Format: `postgres://user:pass@host:port/dbname` | Staging + Prod |
| Migration permissions | Database user must have CREATE TABLE, ALTER TABLE, INDEX rights | First deploy |
| Backup owner | Who runs and monitors automated backups | Prod |
| Backup schedule | Daily/hourly snapshot cadence | Prod |
| Restore drill owner | Who owns and verifies restore drill | Before go-live |
| RPO / RTO targets | Recovery point and recovery time objectives | Before go-live |

**ENV vars produced:**
- `DATABASE_PROVIDER=postgres`
- `DATABASE_URL=postgres://...`

---

## 3. Object Storage (Evidence Documents)

| Input | Description | Required for |
|---|---|---|
| S3 bucket name | Dedicated bucket for evidence documents | Staging + Prod |
| S3 region | AWS region for the bucket | Staging + Prod |
| S3 access key ID | AWS access key with s3:PutObject, s3:GetObject, s3:DeleteObject on the bucket | Staging + Prod |
| S3 secret access key | Corresponding secret — must be stored in a secret manager | Staging + Prod |
| S3 endpoint (if not AWS) | For Minio or other S3-compatible providers | If not AWS |
| Retention policy | How long evidence documents are retained | Prod |
| Evidence signing secret | 32+ char random secret for signed URL generation | Staging + Prod |

**ENV vars produced:**
- `EVIDENCE_STORAGE_PROVIDER=s3`
- `S3_BUCKET`
- `S3_REGION`
- `S3_ACCESS_KEY_ID` (via secret manager)
- `S3_SECRET_ACCESS_KEY` (via secret manager)
- `EVIDENCE_SIGNING_SECRET` (via secret manager)

## 4. Tenant Identity Provider (OIDC)

| Input | Description | Required for |
|---|---|---|
| OIDC issuer URL | e.g. `https://accounts.google.com`, `https://login.microsoftonline.com/tenant-id/v2.0` | Staging + Prod |
| Client ID | OAuth2 client ID for the tenant-facing app | Staging + Prod |
| Client secret | OAuth2 client secret — must be stored in a secret manager | Staging + Prod |
| Redirect URI | `https://<staging or prod URL>/auth/oidc/callback` | Staging + Prod |
| Post-logout redirect URI | `https://<staging or prod URL>/` | Staging + Prod |
| OIDC scopes | At minimum: `openid profile email` | Staging + Prod |
| Test user email | A provisioned user for go-live smoke test | Before go-live |
| Disabled-user test case | A suspended user to verify access denial | Before go-live |

**ENV vars produced:**
- `AUTH_MODE=oidc`
- `OIDC_ISSUER`
- `OIDC_CLIENT_ID`
- `OIDC_CLIENT_SECRET` (via secret manager)
- `OIDC_REDIRECT_URI`
- `OIDC_LOGOUT_REDIRECT_URI`
- `OIDC_SCOPES`

## 7. OCR Provider (Invoice Extraction)

OCR is optional by default (`OCR_REQUIRED=false`). The local deterministic extractor is always available. To enable an external provider, the following inputs are required depending on provider choice.

### Option A: AWS Textract

| Input | Description |
|---|---|
| AWS Access Key ID | IAM user with `textract:AnalyzeDocument` and `textract:StartDocumentAnalysis` permissions |
| AWS Secret Access Key | Corresponding secret — via secret manager |
| AWS Region | Region where Textract is enabled (e.g. `us-east-1`) |

**ENV vars:** `OCR_PROVIDER=aws_textract`, `OCR_ACCESS_KEY`, `OCR_SECRET_KEY`, `OCR_REGION`

### Option B: Azure Document Intelligence

| Input | Description |
|---|---|
| Azure DI endpoint | e.g. `https://<resource-name>.cognitiveservices.azure.com` |
| API key | Azure DI resource key — via secret manager |
| Model ID | e.g. `prebuilt-invoice` |

**ENV vars:** `OCR_PROVIDER=azure_document_intelligence`, `OCR_ENDPOINT`, `OCR_ACCESS_KEY`, `OCR_MODEL_ID`

### Option C: Google Document AI

| Input | Description |
|---|---|
| Processor endpoint | Full processor resource path |
| Bearer token / API key | Service account token or key — via secret manager |
| Model / processor ID | Full processor ID from Google Cloud console |

**ENV vars:** `OCR_PROVIDER=google_document_ai`, `OCR_ENDPOINT`, `OCR_ACCESS_KEY`, `OCR_MODEL_ID`

### Additional (all providers)

| Input | Description |
|---|---|
| Test invoice file | A sample PDF invoice for verify:ocr connectivity test |
| OCR_REQUIRED | Set `true` if go-live should fail when OCR is unconfigured |
| OCR_CONFIDENCE_THRESHOLD | Minimum confidence (default: 0.7) |

## 10. Go-Live Authorization

Before `npm run go-live-check` can pass in production:
- All ENV vars above must be provisioned in a secret manager and injected into the runtime
- `NODE_ENV=production` must be set
- Demo login must be disabled (enforced automatically by NODE_ENV=production)
- Auth bootstrap must report OIDC mode
- `/healthz/ready` must report db=ok, storage=ok, auth=ok
- `/api/dev/demo-login` must return 404

These are verified automatically by `npm run go-live-check`.
