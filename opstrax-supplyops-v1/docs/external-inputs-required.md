# External Inputs Required for Staging / Production Deployment

**Last updated:** 2026-06-17 (Phase 3L — External Services Cutover Readiness)

This document lists exactly what must be provided by the deployment owner before OpsTrax can go live in staging or production. Nothing listed here can be generated by the engineering team — these are external credentials, decisions, and provisioning actions.

**Current status: ALL items below are NOT PROVIDED. No staging deployment can proceed until at minimum items 1–3 are provided.**

---

## 1. Hosting

| Input | Status | Description | Required for |
|---|---|---|---|
| Deployment platform | NOT PROVIDED | AWS, GCP, Azure, Railway, Render, Fly.io, or other | Staging + Prod |
| Staging URL | NOT PROVIDED | Public HTTPS URL for the staging environment | Staging |
| Production URL | NOT PROVIDED | Public HTTPS URL for the production environment | Prod |
| Platform admin URL | NOT PROVIDED | URL for the `/platform/` control plane (may be same host) | Staging + Prod |
| TLS certificate | NOT PROVIDED | Valid TLS cert for staging and production domains | Both |
| Deployment access | NOT PROVIDED | CI/CD credentials or manual SSH/deploy access | Both |

**ENV vars produced:**
- `APP_BASE_URL` / `OPSTRAX_BASE_URL`
- `PLATFORM_BASE_URL` / `OPSTRAX_PLATFORM_BASE_URL`

## 10. Go-Live Authorization

Before `npm run go-live-check` can pass in production, ALL of the above must be resolved:

- `NODE_ENV=production` must be set
- All ENV vars above must be provisioned in a secret manager and injected into the runtime
- Demo login must be disabled (enforced automatically by NODE_ENV=production)
- Auth bootstrap must report OIDC mode for both tenant and platform
- `/healthz/ready` must report db=ok, storage=ok, auth=ok
- `/api/dev/demo-login` must return 404
- `npm run verify:postgres` must pass
- `npm run verify:storage` must pass
- `npm run verify:ocr` must pass (or OCR_REQUIRED=false confirmed)
- `npm run go-live-check` must pass with zero errors

**Current state:** go-live-check returns `ERROR NODE_ENV=production is required` — no external service is configured. This is expected. The check is correctly blocking deployment.
