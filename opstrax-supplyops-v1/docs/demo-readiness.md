# OpsTrax SupplyOps — Demo Readiness Guide

## Quick-Start (local demo)

```bash
NODE_ENV=development OPSTRAX_ALLOW_DEV_CONTEXT=1 npm start
# → http://localhost:9899
```

Open in any modern browser at **1440×900** or wider. Local workspace mode keeps the SSO gate visible and adds a safe secondary entry for the seeded workspace.

### Local and validation ports

- **RC1 local demo:** `http://localhost:9899`
- **Production-validation stack:** `http://localhost:9900`
- The two ports are intentionally separate so the frozen RC1 demo and the production-runtime validation stack can be exercised independently.

### Manual local demo entry

1. Start the app with `NODE_ENV=development OPSTRAX_ALLOW_DEV_CONTEXT=1 npm start`
2. Open `http://localhost:9899`
3. Confirm the SSO gate appears
4. Click **Enter Demo Workspace**
5. Verify the app lands in the seeded IntelliFlow Systems admin workspace
6. If the SSO gate persists, confirm the process was started in development mode and that `OPSTRAX_ALLOW_DEV_CONTEXT=1` is set in the same shell session

### Production-validation stack

1. Start the validation stack with `docker compose -f docker-compose.production-validation.yml up --build`
2. Open `http://localhost:9900`
3. Confirm the production-ready runtime shows readiness checks, not demo bypasses
4. Keep port `9900` reserved for production-style verification only

### Platform admin access

1. Open `http://localhost:9899/platform`
2. Confirm the platform auth gate appears
3. Click **Enter Platform Workspace**
4. Verify the platform dashboard opens with tenant directory, support sessions, security/audit, and system health sections
5. Use the separate platform workspace only for SaaS-owner operations; do not treat it as a tenant login path

## Step-by-Step Demo Script

### Recommended browser: Chrome 1440×900 or wider.

---

### Step 1 — Identity & Session (2 min)

1. Open `http://localhost:9899`
2. Confirm sidebar shows **5 nav groups**: Operations, Procurement & Finance, Trust & Compliance, Execution, Intelligence
3. Confirm topbar shows **IntelliFlow Systems** / **Avery Grant** / **admin**
4. Open DevTools → Network → `/api/me` — show tenant, role, features, scopes
5. **Expected**: tenant `IntelliFlow Systems`, full capabilities, nonzero feature and scope sets

---

### Step 2 — Command Center (2 min)

1. Click **Command Center** (default landing page)
2. Show the KPI strip: Active Items, Low Stock, Open Requests, Purchase Queue, Offline Batches
3. Show the operational queue: any SUBMITTED requests awaiting approval
4. Show the AI Operations panel (read-only, SYSTEM_GENERATED)
5. **Expected**: at least 1 low-stock item, 1 open request visible

---

### Step 3 — Inventory Control (3 min)

1. Click **Inventory Control**
2. Show items table: Nitrile Gloves, Facility Cleaner, Secure Tool Kit (restricted), LED Tubes, HVAC Filters
3. Filter by "medical" — confirm scoped to medical items
4. Click any item → drawer opens with stock balance, bin location, category
5. Click **Add Item** → fill SKU/name/category → save
6. **Expected**: item appears in list, stock shows on-hand count, restricted item is flagged

---

### Step 4 — Request Center → Approve Workflow (5 min)

1. Click **Request Center**
2. Show REQ-2411 (Kitchen Ops, SUBMITTED) in the queue
3. Switch to admin/supervisor → click Approve → confirm status changes to APPROVED
4. Return to **Warehouse Workflows** → warehouse task auto-created for the approved request
5. Click the task → start → pick line → issue
6. Return to **Inventory Control** → confirm stock decreased
7. **Expected**: end-to-end from request to stock movement is visible in audit

---

### Step 5 — Procurement & Receiving (5 min)

1. Click **Procurement Center**
2. Show PR-8812 (MedSupply Direct, PENDING_APPROVAL, $2,840)
3. As admin: approve PR → convert to PO → issue PO
4. Click **Receiving Center** → create receive session from the PO
5. Record received qty → post session
6. Return to **Inventory Control** → stock increased
7. **Expected**: clean receive-to-stock-increase trail

### Step 5b — Procure-to-Pay Intelligence (3 min)

1. Click **Invoice Intelligence**
2. Show the invoice drawer with extraction panel, matching panel, exception queue, approval trail, and export delivery posture
3. Explain that the system surfaces confidence, blockers, and export readiness without pretending to complete a live ERP handoff
4. **Expected**: governed invoice workflow is visible end to end

---

### Step 6 — Finance Export Hub (3 min)

1. Click **Finance Export Hub**
2. Show export candidates (items with value > $0)
3. Create batch → validate → approve → generate
4. Show export validation errors view (any code mismatches flagged)
5. Click **Integration Center** → show ERP connection status and job history
6. **Expected**: blocked batches stay blocked; approval gate is visible

---

### Step 7 — Evidence Vault & Audit Trail (3 min)

1. Click **Evidence Vault** → show documents linked to receive sessions and purchase records
2. Click a document → drawer shows: hash, status, linked record, verifier
3. Click **Audit Trail** → filter by entity type `receive_session`
4. Show: every POST, approval, stock movement, and denial is logged
5. **Expected**: denied actions (e.g. worker attempting to approve) appear as audit events with reason

---

### Step 8 — DeviceOps Center & Offline Sync (3 min)

1. Click **DeviceOps Center**
2. Show: Tablet Receiving 1 (TRUSTED), Warehouse Workstation 3 (TRUSTED)
3. Click **Offline Sync**
4. Show SYNC-4921 (NEEDS_SUPERVISOR_REVIEW) in the conflict queue
5. As supervisor: approve or reject conflicts
6. **Expected**: offline batches require supervisor before posting; trust state persists

---

### Step 9 — AI Operations (3 min)

1. Click **AI Operations**
2. Show `providerStatus: NOT_CONFIGURED` banner
3. Show AI summary cards: low-stock recommendations, open-exception alerts
4. Show source trace: each recommendation links to a real tenant record
5. Show run log: `source: SYSTEM_GENERATED`, no LLM output
6. **Expected**: "Honest AI posture" — system clearly says what it is and what it isn't

---

### Step 10 — Restricted Tenant Security Demo (2 min)

1. Switch to Evostel tenant (`X-Dev-Tenant-Id: tenant_evostel`, any user)
2. Confirm nav shows only 7 modules — no Procurement, Finance, Receiving, DeviceOps
3. Attempt direct API call: `GET /api/purchase-requests` → **403 Forbidden**
4. Open Audit Trail → the denied API call is logged with route + reason
5. **Expected**: Evostel has zero access to IntelliFlow data — all isolation is server-enforced

---

### Step 11 — Admin Panel (1 min)

1. Click **Admin** (admin role only)
2. Show users table: 5 users with roles, departments, facilities
3. Show devices table: 2 trusted devices
4. Switch to requester role → Admin disappears from nav
5. **Expected**: RBAC hides admin nav for non-admin users, server enforces the same

## Known Intentional Limitations

| Area | Status |
|---|---|
| AI LLM Provider | Not connected. All recommendations are rule-based, clearly labeled `SYSTEM_GENERATED`. Integration slot is ready. |
| Evidence File Binaries | Local filesystem in demo. Production requires S3-compatible storage (see `docs/postgres-migration-plan.md`). |
| Invoice OCR | The invoice intelligence surface is live, but OCR/provider-backed extraction remains configured as `NOT_CONFIGURED` in RC1. |
| ERP Dispatch | Export and dispatch posture is real, but live ERP acknowledgment is not claimed unless a connector is configured. |
| Email / Notifications | Not implemented. Events are audit-logged. |
| Rate Limiting | Reverse proxy required for production. |
| PDF Export / CSV Download | Reports catalog is real; PDF/CSV export delivery is implemented and audited. |

## Fallback Troubleshooting

| Symptom | Fix |
|---|---|
| Nav shows 0 groups | Check `NODE_ENV=development`, `OPSTRAX_ALLOW_DEV_CONTEXT=1`, and click **Enter Demo Workspace** |
| All pages show "Feature not enabled" | Tenant feature flags may not be seeded — restart server to run `seedMissingFeatureFlags()` |
| `/api/me` returns 403 | Auth mode is `locked` — set `OPSTRAX_ALLOW_DEV_CONTEXT=1` |
| DB not found error | Check `OPSTRAX_DB_PATH` or remove stale test DB from `data/` |
| `npm run verify-migration` fails | Server hasn't run yet — start once to apply migrations, then re-run |

## Demo Reset / Reseed

Deterministic reseed path:

```bash
rm -f data/opstrax.production.sqlite
NODE_ENV=development OPSTRAX_ALLOW_DEV_CONTEXT=1 npm start
```

The server recreates the SQLite database, applies migrations, and reseeds the full IntelliFlow/Evostel demo dataset on startup. This is the safest way to reset the demo locally.

If you need a conservative rollback, restore the prior `data/opstrax.production.sqlite` backup first, then restart the server. Code rollback is a normal git revert or branch reset to the prior release commit.
