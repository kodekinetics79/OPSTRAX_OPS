# OpsTrax — External Deployment Handoff

**Document version:** Phase 3L-F
**Date:** 2026-06-18
**Prepared by:** OpsTrax Engineering

This document is the single handoff to the deployment owner. It contains exactly what must be provided before any staging or production deployment can proceed. Nothing listed here can be generated by the engineering team.

**Status: ALL items below are NOT PROVIDED. No deployment can proceed until at minimum items 1–4 are provisioned.**

---

## How to use this document

1. Work through each section in order.
2. Provision each value in a secret manager (AWS Secrets Manager, GCP Secret Manager, HashiCorp Vault, Railway variables, Render env, etc.).
3. Inject all ENV vars into the runtime at deploy time — never commit them to source control.
4. Run the verification commands listed in each section after provisioning.
5. Run `npm run go-live-check` when all items are done — it will fail with a clear error until every required ENV var is set.

---

## 1. Base URLs

```
APP_BASE_URL=https://<your-staging-or-production-domain>
PLATFORM_BASE_URL=https://<your-staging-or-production-domain>
```

The two values may be identical if the platform admin control plane shares the same host. The tenant workspace is at `/` and the platform admin is at `/platform/`.

**Required for:** staging + production

---

## 2. Database

```
DATABASE_PROVIDER=postgres
DATABASE_URL=postgres://user:password@host:5432/dbname
```

The database user must have CREATE TABLE, ALTER TABLE, CREATE INDEX, INSERT, UPDATE, DELETE permissions on the target database. Migrations are applied automatically on startup.

**Required for:** staging + production

**Verification command (after provisioning):**
```
DATABASE_URL=<url> npm run verify:postgres
```

---

## 3. Object Storage (Evidence Documents)

```
EVIDENCE_STORAGE_PROVIDER=s3
S3_BUCKET=<bucket-name>
S3_REGION=<aws-region>            # e.g. us-east-1
S3_ACCESS_KEY_ID=<iam-key-id>     # store in secret manager
S3_SECRET_ACCESS_KEY=<iam-secret> # store in secret manager
EVIDENCE_SIGNING_SECRET=<random-32-char-string>  # store in secret manager
```

The IAM user must have `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject` on the bucket. No public access required.

For MinIO or other S3-compatible storage, also set:
```
S3_ENDPOINT=https://<minio-host>
S3_FORCE_PATH_STYLE=true
```

**Required for:** staging + production

**Verification command (after provisioning):**
```
S3_BUCKET=... S3_REGION=... S3_ACCESS_KEY_ID=... S3_SECRET_ACCESS_KEY=... npm run verify:storage
```

## 4. Tenant Identity Provider (OIDC)

```
OIDC_ISSUER=https://<your-idp>/.well-known/openid-configuration  # issuer URL, not the well-known URL
OIDC_CLIENT_ID=<oauth2-client-id>
OIDC_CLIENT_SECRET=<oauth2-client-secret>  # store in secret manager
OIDC_REDIRECT_URI=https://<app-base-url>/auth/oidc/callback
OIDC_LOGOUT_REDIRECT_URI=https://<app-base-url>/
OIDC_SCOPES=openid profile email
```

Example values for common providers:
- Google: `OIDC_ISSUER=https://accounts.google.com`
- Microsoft Entra: `OIDC_ISSUER=https://login.microsoftonline.com/<tenant-id>/v2.0`
- Auth0: `OIDC_ISSUER=https://<domain>.auth0.com/`
- Okta: `OIDC_ISSUER=https://<domain>.okta.com/oauth2/default`

**Required for:** staging + production

---

## 5. Platform Identity Provider (OIDC)

```
PLATFORM_OIDC_ISSUER=<same-or-different-idp>
PLATFORM_OIDC_CLIENT_ID=<platform-client-id>
PLATFORM_OIDC_CLIENT_SECRET=<platform-client-secret>  # store in secret manager
PLATFORM_OIDC_REDIRECT_URI=https://<app-base-url>/platform/auth/oidc/callback
PLATFORM_OIDC_LOGOUT_REDIRECT_URI=https://<app-base-url>/platform/
PLATFORM_OIDC_SCOPES=openid profile email
```

The platform IdP may be the same IdP as the tenant IdP (with a separate client registration) or a separate internal IdP.

**Required for:** staging + production

## 6. Session Secrets

```
SESSION_SECRET=<random-32+-char-string>          # store in secret manager
PLATFORM_SESSION_SECRET=<random-32+-char-string> # store in secret manager
COOKIE_SECURE=true
COOKIE_SAME_SITE=lax
```

Generate with: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

**Required for:** staging + production

## 7. OCR Provider (Invoice Extraction)

OCR is optional. The local deterministic extractor is always available. To enable AWS Textract:

```
OCR_PROVIDER=aws_textract
OCR_ACCESS_KEY=<iam-access-key-id>      # store in secret manager
OCR_SECRET_KEY=<iam-secret-access-key>  # store in secret manager
OCR_REGION=us-east-1                    # or the correct region
```

The IAM user must have `textract:AnalyzeExpense` permission.

Optional:
```
OCR_REQUIRED=true                   # fail startup if OCR is unconfigured (default: false)
OCR_CONFIDENCE_THRESHOLD=0.7        # minimum confidence for proposed fields (default: 0.7)
```

**Azure Document Intelligence (alternative):**
```
OCR_PROVIDER=azure_document_intelligence
OCR_ENDPOINT=https://<resource>.cognitiveservices.azure.com
OCR_ACCESS_KEY=<api-key>
OCR_MODEL_ID=prebuilt-invoice
```

**Verification command (when configured):**
```
OCR_PROVIDER=aws_textract OCR_ACCESS_KEY=... OCR_SECRET_KEY=... OCR_REGION=... npm run verify:ocr -- --probe
```

**Required for:** optional; strongly recommended for production

## 8. Runtime Environment

```
NODE_ENV=production
PORT=<port>   # platform-assigned port, or 9899
```

`NODE_ENV=production` enforces:
- Demo login endpoints disabled (return 404)
- PostgreSQL required (SQLite not accepted)
- Secure cookies enforced
- Startup check runs and fails fast if any required var is missing

## 9. Monitoring and Alerting

OpsTrax logs structured output to stderr. External monitoring must be configured by the deployment owner.

**Required decisions:**

| Item | Decision needed |
| --- | --- |
| Monitoring provider | Datadog, CloudWatch, PagerDuty, UptimeRobot, etc. |
| Uptime check URL | `https://<app-base-url>/healthz/ready` must return HTTP 200 |
| Alert destination | Webhook URL, email, Slack channel |
| Oncall contacts | Who receives alerts for platform errors |
| Error rate SLA | Acceptable p95 latency and error rate threshold |

The `/healthz/ready` endpoint returns JSON with `db`, `storage`, and `auth` status — it can be used as the healthcheck target.

## 10. Backup and Restore

| Item | Decision needed |
| --- | --- |
| Backup provider | Postgres host-managed, RDS automated backup, pg_dump cron, etc. |

## 12. Final Go-Live Checklist

After all items above are provisioned, run:

```bash
# 1. Confirm migration version
npm run verify-migration           # expected: v28

# 2. Confirm database connection
npm run verify:postgres

# 3. Confirm storage connection
npm run verify:storage

# 4. Confirm OCR (if using external provider)
npm run verify:ocr -- --probe

# 5. Run full go-live check (requires NODE_ENV=production and all ENV vars)
NODE_ENV=production npm run go-live-check

# 6. Confirm health endpoint
curl https://<app-base-url>/healthz/ready
```

All commands must pass with zero errors before go-live is authorized.

**Demo login must return 404 in production:**
```bash
curl -X POST https://<app-base-url>/api/dev/demo-login
# Must return: {"error":"Not found"}  (HTTP 404)
```
